# AI Content Studio V1

Windows desktop application starter for parallel AI article generation and WordPress draft delivery.

## Windows builds (64-bit x64)

This project is configured to produce **two separate Windows x64 distributions**:

1. **Standard Installer (NSIS)** — installs AI Content Studio on one Windows computer, creates Start Menu and optional Desktop shortcuts, and lets the user choose the installation folder. Its database and settings stay in that Windows user's normal Electron AppData location.
2. **Portable Version** — a single portable launcher that can be run from a USB drive or folder without a conventional installation. On first launch it creates `AI-Content-Studio-Data` beside the portable EXE. The SQLite database and Electron user/session data are stored there. Keep this folder with the portable EXE when moving the app.

Both builds explicitly target **Windows x64**. They are intended for Windows 10/11 64-bit; they are not macOS, Linux, or 32-bit builds.

### Build both versions on Windows

Use Windows 10/11 x64 with Node.js 20 LTS or newer and npm. Open PowerShell in the extracted project directory and run:

```powershell
npm install
npm run dist:win
```

Output files:

- `release/standard/AI-Content-Studio-Setup-1.0.0-x64.exe`
- `release/portable/AI-Content-Studio-Portable-1.0.0-x64.exe`

You can build only one format:

```powershell
npm run dist:installer
npm run dist:portable
```

The Windows build should be run on Windows (or a configured Windows x64 build runner), then both EXEs should be tested on a clean Windows 10/11 x64 computer before distribution. These are unsigned builds unless a code-signing certificate is configured; Windows SmartScreen may show an unknown-publisher warning.

### Portable data and credentials

The portable database is stored at:

`<folder-containing-portable-exe>\\AI-Content-Studio-Data\\studio.sqlite`

Do not remove that folder if you want to keep the portable app's sites, articles, schedules, and settings. Back it up before moving or updating the app. Windows credential encryption may be tied to the Windows user/device, so encrypted provider credentials might not be usable after moving the data folder to a different computer or Windows account; re-enter API keys if required. The USB/folder must be writable.

## Included in this V1 source
- Electron + React + TypeScript desktop shell
- SQLite local database
- Gemini, Groq and OpenRouter parallel generation adapters
- Website manager using the existing MadCraves protocol:
  - `POST /wp-json/madcraves/v1/draft`
  - `X-MadCraves-Token: <token>`
- WordPress draft submission
- Article library and dashboard
- Basic schedule storage and due notifications (confirmation-first; no unattended publishing)
- Provider key encryption using Electron `safeStorage` when available

## Run in development
1. Extract this project.
2. Open PowerShell in the project folder.
3. Run `npm install`.
4. Run `npm run dev`.

## Configure providers
Open **AI Providers** and add provider/model/API key. Use model IDs currently enabled in your provider account:
- Gemini: e.g. `gemini-2.0-flash`
- Groq: e.g. `llama-3.3-70b-versatile`
- OpenRouter: e.g. `openai/gpt-4o-mini`

Provider models and availability change. Check each provider's current model catalogue before configuring.

## WordPress connection
Add the website URL and the receiver token generated by your existing MadCraves receiver plugin. The app posts to:
`https://YOUR-SITE/wp-json/madcraves/v1/draft`

The payload includes title, HTML content, excerpt, draft status, slug and common SEO metadata keys. The receiver plugin must explicitly register and map metadata for the installed SEO plugin; WordPress may reject unregistered custom meta fields.

## V1 limitations / next engineering tasks
This is a development starter, not yet a signed, fully QA-tested production release:
1. Confirm the exact request/response contract of the existing MadCraves receiver plugin. This app intentionally does not change its token protocol.
2. Add a WordPress receiver integration test against a staging site.
3. Implement robust schema validation, retry/backoff, cancellation, job progress and per-provider usage/cost tracking.
4. Add article editing UI and save selected provider output to the library (currently all successful versions are saved; comparison preview is shown).
5. Implement image generation using a selected image-capable provider/model, upload media to WordPress and set featured image/alt text. The UI extension point is present; image generation is not yet implemented.
6. Implement internal-link discovery from each site's sitemap and a reviewable link insertion step. The current prompt accepts supplied internal links but does not crawl a site.
7. Upgrade scheduler to execute queued generation after explicit user opt-in and persistently recover missed jobs after restart. Current V1 sends a due notification only.
8. Add full SEO plugin detection and version-specific metadata mapping (Rank Math, Yoast, AIOSEO), plus verification by reading the created draft.
9. Add secure credential migration, database backup/restore, logs UI and signed installer.

## Security notes
- Keep API keys private. Do not share the SQLite database.
- Do not expose WordPress tokens in logs.
- Use HTTPS WordPress sites and dedicated least-privilege credentials.
- Review AI-generated content and citations before publication.

## One-click portable build (no PowerShell)

On a Windows 10/11 x64 computer, install the Node.js LTS release once if it is not already installed. Then double-click `BUILD-PORTABLE.bat`. It installs the project dependencies, builds only the portable x64 application, and opens `release/portable/` when complete. No PowerShell commands are required; the batch file runs in Command Prompt.
